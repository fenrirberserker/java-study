## Shortest-Path Algorithms

- **Dijkstra's algorithm**: single-source shortest path for graphs with non-negative edge weights. Greedily expands the frontier by always finalizing the currently-closest unvisited vertex, typically implemented with a min-priority queue keyed on tentative distance. Time complexity O((V + E) log V) with a binary heap. Fails silently (produces wrong answers, not an error) on graphs with negative edge weights, because the greedy "closest vertex is final" assumption breaks once a longer path could later be shortened by a negative edge.
- **Bellman-Ford algorithm**: single-source shortest path that tolerates negative edge weights (but not negative cycles reachable from the source, which make "shortest path" undefined — distance can be driven arbitrarily low by looping the cycle). Repeatedly **relaxes every edge** (updates `d[v] = min(d[v], d[u] + cost(u,v))`) for up to V-1 rounds, where V is the vertex count. 
  - **Why V-1 rounds, precisely**: any shortest path between two vertices in a graph with V vertices uses at most V-1 edges (a simple path cannot revisit a vertex without it being either irrelevant or evidence of a negative cycle). Each full relaxation round is guaranteed to correctly extend the shortest known path by at least one more edge along the correct edge-discovery order in the worst case, so after V-1 rounds every shortest path (up to V-1 edges long) is guaranteed found regardless of the order edges happen to be processed in. Best case (favorable edge order) can converge in as little as 1 round; the V-1 bound is the guaranteed worst-case upper bound, not a typical case.
  - **Negative-cycle detection**: run one additional (Vth) relaxation round after the normal V-1; if any edge can still be relaxed (distance still decreases), the graph contains a negative cycle reachable from the source, since a converged shortest-path assignment should be stable under a redundant relaxation pass.
  - Time complexity O(V·E), notably worse than Dijkstra's, which is the trade-off for tolerating negative weights.
- **Floyd-Warshall algorithm**: all-pairs shortest path (every vertex to every other vertex in one run), via dynamic programming over "shortest path using only the first k vertices as intermediates," for k = 1..V. O(V^3) time, O(V^2) space — preferable to running Dijkstra/Bellman-Ford from every vertex individually when the graph is dense or all-pairs distances are actually needed, but scales poorly to large sparse graphs.
- **A\* (A-star) pathfinding**: an informed generalization of Dijkstra that adds a heuristic estimate `h(n)` of remaining distance to the goal, ordering the frontier by `f(n) = g(n) + h(n)` (cost-so-far plus estimated cost-to-go) instead of `g(n)` alone. Guaranteed optimal (finds the true shortest path) if the heuristic is **admissible** (never overestimates true remaining cost) — this is the standard interview/game-development answer for "why does A* still find the optimal path despite using a heuristic." Grid pathfinding (e.g., maze solving, the classic 8-puzzle) and game-AI navigation are the canonical applications; Euclidean or Manhattan distance to the goal are common admissible heuristics depending on allowed movement directions.

## Minimum Spanning Tree (MST) Algorithms

Both solve: given a connected, weighted, undirected graph, find the subset of edges connecting all vertices with minimum total edge weight and no cycles.

- **Prim's algorithm**: grows a single tree from an arbitrary start vertex, at each step adding the cheapest edge connecting the current tree to a vertex not yet included. Naive adjacency-matrix implementation is O(V^2); with a priority queue over candidate edges, O(E log E), improvable to O(E log V) with a binary heap. Conceptually similar to Dijkstra (both grow a structure greedily by cheapest next edge) but optimizing a different quantity — Prim's minimizes total tree weight, Dijkstra's minimizes distance from a fixed source.
- **Kruskal's algorithm**: sorts all edges by weight ascending, then greedily adds each edge unless it would create a cycle, using a **disjoint-set (union-find)** data structure to test cycle membership in near-constant time. O(E log E) dominated by the initial sort. Generally preferred over Prim's on sparse graphs; Prim's is often preferred on dense graphs where the vertex count dominates.
- Both are textbook examples of the **greedy-algorithm-with-optimal-substructure** proof pattern covered generally in `doc/Study.md`'s Greedy section — worth connecting explicitly: MST construction is one of the few problems where a purely greedy local choice (cheapest available edge) is provably globally optimal, unlike many other greedy heuristics that only approximate.

## String-Matching / Substring Search

- **Knuth-Morris-Pratt (KMP)**: finds all occurrences of a pattern string within a text in O(n + m) time (n = text length, m = pattern length), versus O(n·m) for naive substring search. The key idea is precomputing a "failure function" / longest-prefix-suffix (LPS) table for the pattern itself, so that after a partial match fails, the search can skip ahead without re-examining text characters already known to match — the algorithm never backtracks the text pointer, only the pattern pointer.
- **Rabin-Karp**: finds pattern occurrences using a rolling hash — compute the pattern's hash once, then slide a window across the text recomputing the window's hash incrementally (O(1) update per shift) and only doing a full character-by-character comparison when hash values match (to rule out hash collisions). Average case O(n + m), worst case O(n·m) under pathological hash collisions. Particularly well-suited to **multi-pattern search** (checking many patterns against one text, or plagiarism-detection-style substring matching) since multiple pattern hashes can be checked against the same rolling window cheaply.

## Specialized / Niche Algorithms

- **Catalan numbers**: a combinatorial sequence (1, 1, 2, 5, 14, 42, ...) that counts the number of valid balanced-parenthesis sequences, binary search tree shapes for n keys, and polygon triangulations, among other structurally-recurring combinatorial problems — recognizing "this problem's answer follows Catalan numbers" is itself a shortcut for a class of counting problems that would otherwise require deriving a recurrence from scratch.
- **Bresenham's line-drawing algorithm**: a classic computer-graphics algorithm for rasterizing a straight line between two points using only integer arithmetic (no floating-point division), by tracking a running "decision parameter" that determines whether the next pixel step should move diagonally or axis-aligned. Rarely relevant to backend work directly, but a good example of an algorithm designed specifically to avoid floating-point cost on constrained hardware — the same "replace division/float math with incremental integer updates" trick reappears in other performance-sensitive numeric code.
- **Fast Fourier Transform (FFT)**: computes the Discrete Fourier Transform of a sequence in O(n log n) instead of the naive O(n^2), via a recursive divide-and-conquer decomposition (splitting into even/odd-indexed subsequences). Foundational for signal processing, but also a standard trick for fast polynomial multiplication (multiplying two degree-n polynomials in O(n log n) instead of O(n^2) by transforming to point-value form, multiplying pointwise, then inverse-transforming) — worth knowing as a named technique if a problem's brute-force complexity bottleneck is literally a convolution or polynomial multiplication.
- **Dynamic Time Warping (DTW)**: a dynamic-programming technique for measuring similarity between two time series that may be misaligned or vary in speed (e.g., comparing spoken audio at different speaking rates), by finding an optimal non-linear alignment/warping between them rather than a fixed one-to-one comparison. Relevant if working on time-series matching, gesture recognition, or audio fingerprinting.
- **Matrix exponentiation**: computes the nth term of a linear recurrence (the canonical example is Fibonacci) in O(log n) matrix multiplications instead of O(n) iterations, by expressing the recurrence as a matrix power and using fast exponentiation-by-squaring. Useful whenever a recurrence relation needs to be evaluated at very large n (millions/billions) where even O(n) is too slow.
- **Multithreaded algorithm patterns**: the book covers multithreaded matrix multiplication and multithreaded merge sort as canonical examples of the fork-join divide-and-conquer parallelization pattern (split the problem, solve subproblems on separate threads, merge results) — conceptually the same shape as the fork/join framework covered in more Java-specific depth in `doc/references/Java/ocp-java-se8-programmer-2.md`.
- **Online algorithms / paging**: algorithms that must make irrevocable decisions with only partial (past) information, unlike offline algorithms that see the whole input in advance — the book's example is page-replacement/caching policy (deciding what to evict from a fixed-size cache without knowing future access patterns). This distinction (online vs. offline) is directly relevant to real cache-eviction-policy design (Least Recently Used, or LRU, and its approximations are online algorithms) and is a useful vocabulary distinction for system-design discussions.
- **Classic dynamic programming problems** also covered (Edit Distance/Levenshtein distance, Longest Common Subsequence, Longest Increasing Subsequence, 0/1 Knapsack, Travelling Salesman via DP with bitmask state) largely reinforce the DP fundamentals already in `doc/Study.md`; the specific recurrences are standard and not reproduced here to avoid duplication — see `doc/Study.md`'s Dynamic Programming section for the general 5-step design recipe these all instantiate.

## Takeaways for a Senior Backend Java Developer

- The single most interview-relevant addition versus `doc/Study.md`'s existing graph coverage is the **shortest-path algorithm family decision tree**: unweighted graph -> BFS; non-negative weights -> Dijkstra; possible negative weights (no negative cycles) -> Bellman-Ford; all-pairs needed -> Floyd-Warshall; have a good admissible heuristic and a single target -> A*. Being able to state this decision tree crisply is a strong signal in a system-design or algorithms interview.
- KMP and Rabin-Karp are worth having crisp mental summaries of even if `String.indexOf()`/`Pattern.matcher().find()` (built on similar or better algorithms internally) is what's actually used in production code — understanding *why* naive substring search is O(n·m) and how these algorithms avoid it is a common interview probe.
- The MST algorithms (Prim's/Kruskal's) are a clean, concrete example to reach for when explaining "when is greedy provably optimal" versus when greedy is just a heuristic approximation — a genuinely useful teaching example beyond just certification/interview trivia.
